# EV6 KR 뮤직 무드램프

국내형 기아 EV6(`CVEV.KOR`, 펌웨어 260902, Gen5W 내비)에서 **실내 마이크로 들리는 음악에 맞춰 실내 무드 조명의 색과 밝기를 바꾸는** HMG-API 모드입니다.
- 앱 메뉴에 **전용 타일**(홈 화면 편집에서 홈에 둘 수 있음)
- 켜기/끄기와 모든 설정을 담은 **앱 화면**
- **★ 버튼**에 지정할 수 있는 켜기/끄기

> [!WARNING]
> **모든 사용은 본인 책임입니다.** 비공식 개인 프로젝트이며 어떤 보증도 하지 않습니다. 현대자동차·기아·현대모비스와 관계없습니다.
> **시험과 설정은 정차한 상태에서 하세요.** 주행 중에 USB를 꽂거나 화면과 조명을 살피는 것은 위험합니다.

> **상태 (2026-11-12): v0.2.2**
> - **차에서 확인:** 음악에 맞춰 무드 조명의 색과 밝기가 바뀝니다. 켜 둔 동안에도 Siri와 카플레이 통화가 정상이고, 시동 후 켜짐이 유지됩니다. 차량 설정의 '드라이브 모드 연동'은 꺼야 합니다.
> - **알려진 제약:** 실내 마이크로 듣는 방식이라 주행 소음에도 어느 정도 반응합니다. [알려진 제약](#알려진-제약)을 참고하세요.

## 준비물

- **국내형 기아 EV6**, 내비 소프트웨어 `CVEV.KOR.….260902`. 다른 차종이나 펌웨어에는 설치되지 않습니다.
- [NEMESIS](https://github.com/xwtk/hmg_nemesis)와 [HMG-API](https://github.com/Open-HMG/HMG-API) 1.0.2
- 차량 설정 › 실내 무드 조명 › **'드라이브 모드 연동' 끄기**. 켜져 있으면 차가 커스텀 색을 무시하고 밝기만 바뀝니다.

## 동작 방식

1. 마이크 소리를 16kHz, 64ms 단위로 분석합니다(녹음·저장 없음).
   - **밝기:** 최근 몇 초 평균보다 큰 소리일수록 밝아집니다. 평균이 40%이고, 감도 5에서 +10dB이면 최대입니다.
   - **색:** 다섯 대역(저음 40-150Hz, 중저음 -400Hz, 중음 -1.5kHz, 중고음 -4kHz, 고음 -8kHz) 가운데 **평소보다 가장 크게 솟은 대역**의 색을 씁니다. 그래서 늘 에너지가 큰 베이스만 따라가지 않습니다.
   - 배경(도로 소음, 공조)보다 크지 않으면 '조용함'으로 보고, 밝기를 최소로 낮추고 색은 그대로 둡니다.
   - **주행 소음:** 대역마다 자기 정상 소음 바닥을 따로 추적합니다. 그보다 충분히(감도 5에서 6.5dB) 솟은 대역만 색을 가져갈 수 있습니다. 주행 중에는 차속에 따라 문턱을 더 올립니다. 테스트의 강한 도로 소음 모델에서 소음만으로 생기는 색 변경은 시속 30km에서 30초에 약 2번, 60km 이상에서는 0번이었고, 같은 소음 위의 음악에는 계속 반응했습니다.
2. 차 조명은 **순정 차량 설정 앱이 커스텀 색과 밝기를 바꿀 때와 같은 호출**로 바꿉니다.
   - `ISystemService.setSMLRGB`(색), `setSMLConfiguration(5, 밝기)`(밝기)
   - 주행 중 감광, 드라이브 모드 연동, 페이드 설정은 건드리지 않습니다.
   - 변경 간격은 150-300ms, 색은 0.3-1.5초 동안 유지합니다(초당 약 2.5-5회). MICOM 링크를 다른 기능과 함께 쓰기 때문입니다.
   - 색은 설정 앱 색상표의 64색만 씁니다.
3. 켤 때 차에 현재 조명을 물어 저장하고, **끌 때 그 색과 밝기로 되돌립니다.** 켜 둔 동안 메뉴에서 조명을 바꾸면, 끌 때 그 새 조명으로 되돌립니다.
4. 주행 여부는 차 시스템 서비스의 차속(`getVehicleSpeed`, 5km/h 이상이면 주행)으로 판단합니다.

## 설치 (USB)

1. **정차한 상태에서** 차량 설정 › 실내 무드 조명 › **'드라이브 모드 연동'을 끕니다.** 앱 화면에도 경고가 뜹니다.
2. [Releases](https://github.com/hwjang1/ev6kr-ambient-music/releases)에서 `ambient-music-kr-<버전>-nemesis.zip`을 받아, **안의 내용물**을 USB 최상위에 풉니다(`packages/` 안의 zip은 풀지 않음). 꽂으면 NEMESIS가 설치를 묻습니다.
   - USB 메모리는 FAT32나 exFAT로 포맷합니다. 맥에서 복사했다면 '꺼내기'를 한 뒤 뽑아 주세요.
   - USB 데이터 포트가 하나뿐인 차는 설치하는 동안 Wi-Fi 동글을 뺍니다. 그동안은 무선 카플레이가 연결되지 않습니다.
   - 모드 서명 키는 [ev6kr-wireless-carplay](https://github.com/hwjang1/ev6kr-wireless-carplay)와 같은 `e4015807-…`입니다. 처음 설치하면 HMG-API가 '알 수 없는 작성자' 경고를 띄울 수 있습니다.
3. 스틱을 빼고 동글을 꽂은 뒤 **헤드유닛을 한 번 재시작합니다.** 앱 메뉴 타일과 ★ 항목은 재시작 때 읽힙니다.
4. 앱 메뉴의 **뮤직 무드램프**를 한 번 엽니다. 설치 직후의 앱은 한 번 열기 전까지 ★ 버튼 신호를 받지 못합니다.

## 마이크 공유

이 차의 마이크는 음성용 DSP(FM1288: 핸즈프리, Siri, 음성인식)를 거칩니다. 카플레이는 Siri와 통화 때 녹음 장치를 tinyalsa로 직접 열고, 장치가 사용 중이면 몇 번만 다시 시도합니다(순정 `libCarPlayAudio.so`). Android 4.4는 녹음을 한 번에 하나만 허용합니다. 그래서 이 앱이 마이크를 잡고 있으면 **Siri나 카플레이 통화가 마이크를 못 열 수 있습니다.**

다음 신호를 받으면 **수신 즉시 녹음을 멈추고** 30초 동안 마이크를 비웁니다. 신호가 다시 오면 30초가 새로 시작됩니다.
- `com.hkmc.siri.widgetupdate`: DiPO가 카플레이 speech mode가 켜지고 꺼질 때 보냄. 런처 페이지 변경이나 위젯 갱신 요청 뒤 1.5초 안에 온 것은 위젯 갱신의 메아리로 보고 무시합니다(0.2.2).
- `com.hkmc.carplay.call.widgetupdate`: 카플레이 통화 상태가 바뀔 때
- `com.mobis.intent.action.VR_ACTIVITY_BEGIN`: 차 음성인식 시작
- 음성·통화 버튼(`VR_PTT_SHORTCUT`, `CARPLAY_CALL_SHORTCUT`, 각각의 `_LONG`)
- Android 오디오 모드가 통화 중일 때

마이크를 놓고 다시 잡는 기록은 경고 레벨(`AmbientMusic`)로 남깁니다. ev6kr.usbap.sync의 디버그 로그캣에 남기기 위해서입니다.

## 차량에서 확인할 것 (정차 중에)

순서대로 해 주세요. 0.1.0에서 카플레이가 안 된 원인을 가리기 위한 순서입니다.

1. 설치하고 재시작한 뒤 **앱을 켜지 않은 상태에서** 무선 카플레이가 평소처럼 연결되는지.
2. 앱 화면에 '차 무드램프: #색 · 밝기 · 드라이브 모드 연동 꺼짐'이 나오는지.
3. 앱을 켜고 음악을 틀었을 때 무드 조명의 색과 밝기가 바뀌는지, 앱 왼쪽 마이크 dB가 음악에 반응하는지. 반응이 약하면 **마이크 경로**를 '음성인식 경로'로 바꿔 봅니다.
4. **앱을 켠 상태에서** 카플레이 음악, Siri(음성 버튼, "시리야"), 카플레이 전화(걸기·받기, 통화 버튼과 화면 터치 둘 다)가 정상인지. 앱 화면에 'Siri·통화: 마이크를 비워 둠'이 뜨는지도 봐 주세요. **문제가 있으면 바로 끄고, 5분 안에 진단 스틱(`ev6kr-ambient-diag-usb.zip`)을 돌려 주세요.** ev6kr.usbap.sync의 디버그 로그캣은 약 10분치만 남습니다.
5. 주행 중 도로 소음만으로 색이 바뀌는 정도. 많으면 '주행 소음 억제'를 '강하게'로 바꿔 봅니다.
6. 끄기를 누르면 원래 색과 밝기로 돌아오는지. 켜 둔 채 시동을 껐다 켰을 때 다시 켜지는지(부팅 뒤 약 15초), 그 뒤에 끄면 시동 전의 원래 조명으로 돌아오는지.
7. ★ 버튼 켜기/끄기, 타일 아이콘(주간·야간).

로그 태그는 `AmbientMusic`입니다.

## 알려진 제약

- **주행 소음:** 실내 마이크로 듣기 때문에 도로·바람 소음도 음악과 같은 소리로 들어옵니다. 주행 소음 억제는 문턱을 올리는 방식이라, 강하게 할수록 음악에도 덜 반응합니다. 마이크 방식의 한계로 남겨 둡니다. 거슬리면 다음을 써 보세요(설정 변경은 정차 중에).
  - '주행 소음 억제'를 '강하게'로
  - '마이크 경로'를 '음성인식 경로'로(차의 음성 DSP가 꾸준한 소음을 줄일 수 있음, 차에서 확인 전)
  - '주행 중'을 '일시정지(원래 조명)'로
- **대화:** 사람 목소리에도 반응합니다.
- **마이크 양보 중 정지:** Siri, 카플레이 통화, 차 음성인식이 시작되면 30초 동안 마이크를 비우고, 그동안 조명은 멈춥니다. 앱 화면에 이유가 나옵니다.
- **드라이브 모드 연동:** 켜져 있으면 차가 커스텀 색을 무시하고 밝기만 바뀝니다.

## 빌드

```sh
tools/build.sh keygen   # 처음 한 번: 앱 서명 키 (~/hmg-private/keys/ev6kr-ambient-music.p12, 저장소 밖)
tools/build.sh          # 테스트 → APK → 서명된 모드 → NEMESIS USB 패키지, 진단 스틱 (dist/)
tools/build.sh test     # 차 없이 분석·전송 로직만 테스트
tools/build.sh usmtest  # USM 시험 스틱
tools/icons.sh          # art/glyph.svg에서 타일 아이콘 다시 만들기 (rsvg-convert)
```

필요한 것:
- JDK와 Android SDK(build-tools의 aapt2, d8, zipalign, apksigner)
- 옆 폴더의 HMG-API 소스(`../HMG-API`): hmgapi-client, 모드 서명, NEMESIS 패키지 생성에 쓰며 읽기만 합니다.
- 모드 서명 키는 wireless-carplay-kr과 같은 `~/hmg-private/keys/ev6kr-mods.key`입니다.

**앱 키와 모드 키는 백업해 두세요.** 키가 바뀌면 업데이트가 설치되지 않습니다.

## 변경 이력

- **0.2.2** (차에서 확인: 주행 소음 억제 외 정상, 2026-11-12)
  - DiPO는 Siri·통화 위젯 신호를 홈 화면 위젯을 갱신할 때도 다시 보냅니다(페이지 변경, 위젯 갱신 요청, 카플레이 연결과 무관). 0.2.1은 이것까지 Siri로 보고 마이크를 30초씩 쉬어서, 홈 화면에서는 멈춘 것처럼 보일 수 있었습니다. 이제 갱신 요청 뒤 1.5초 안에 오는 위젯 신호는 무시하고, 앱 화면에 마이크를 쉬는 이유를 보여줍니다.
  - 켜짐 유지: 켜 둔 채 시동을 끄면 다음 부팅 때 다시 켜집니다(부팅 15초 뒤 시작, 차 서비스 연결을 1분 동안 재시도). '자동 시작' 항목은 이것으로 대체했습니다.
  - 차량 설정 앱은 차가 보고하는 조명을 그대로 저장합니다. 켜 둔 채 꺼지면 음악의 마지막 색이 저장되므로, 원래 조명을 앱에도 저장해 두었다가 직접 끌 때 그 조명으로 되돌립니다.
- **0.2.1**
  - 0.2.0을 켠 동안 카플레이 전화(통화 버튼)와 Siri(음성 버튼)가 제대로 동작하지 않았습니다. 카플레이가 Siri·통화 상태를 바꿀 때 보내는 신호를 받으면 그 자리에서 녹음을 멈추고 30초 동안 마이크를 비우게 했습니다.
  - 주행 소음에도 색이 자주 바뀌었습니다. 대역마다 정상 소음 바닥을 추적하고, 차속에 따라 문턱을 올리는 주행 소음 억제를 넣었습니다(설정에서 강도 선택).
- **0.2.0** (차에서 확인: 음악에 맞춰 색과 밝기가 바뀜)
  - 순정 차량 설정 앱이 커스텀 색과 밝기를 바꿀 때와 같은 차 조명 호출을 앱에서 직접 합니다. HMG-API 차량 서비스는 쓰지 않습니다.
  - 켤 때 원래 조명을 저장하고 끌 때 되돌립니다. 드라이브 모드 연동이 켜져 있으면 경고합니다.
- **0.1.0** (차에서 실패)
  - HMG-API의 `ambient_light` 명령을 썼습니다. 무드 조명은 바뀌지 않았고, 설치된 동안 무선 카플레이가 연결되지 않았습니다.
  - 진단 결과, 색이 안 바뀐 이유는 '드라이브 모드 연동'이 켜져 있었기 때문입니다. 카플레이가 안 된 부팅에서 앱은 명령을 하나도 보내지 않았습니다. 이 모드 때문에 처음 켜진 HMG-API 차량 서비스가 가장 큰 용의자입니다(확정은 못 함).

## 출처

- 마이크 FFT로 무드램프를 바꾸는 방식은 nmz787의 [gen5w-ambient-sound](https://github.com/nmz787/gen5w-ambient-sound)에서 착안했습니다. 코드는 가져오지 않고 새로 작성했습니다.
- 64색 팔레트와 2바이트 색 형식은 [HMG-API](https://github.com/Open-HMG/HMG-API)(AGPL-3.0)의 `ambient_light` 연구를 따랐습니다. APK에는 HMG-API의 `hmgapi-client`가 들어갑니다(연결 상태 확인과 차 알림에 사용).
- 설정 값의 뜻(모드 번호, 상태 바이트, 드라이브 모드 연동)은 이 차의 순정 차량 설정 앱을 분석해 확인했습니다. 앱 자체는 저장소에 넣지 않습니다.
